## 🎯 优先级调整说明（内网环境）

由于项目主要部署在内网环境，我们对原始审查报告的优先级进行了如下调整：

### 降低优先级的问题

| 问题 | 原优先级 | 新优先级 | 理由 |
|------|---------|---------|------|
| Dashboard登录暴力破解防护 | P0-严重 | **P2-建议** | 内网环境外部攻击风险低 |
| CSRF保护 | P0-严重 | **P2-建议** | 内网环境跨站攻击风险低 |
| 路径穿越（Cookie删除） | P0-严重 | **P1-重要** | 内网环境降低风险但仍需修复 |

### 保持高优先级的问题

以下问题即使在内网环境也必须立即修复：

1. **JWT密钥持久化** (P0) - 影响用户体验
2. **Promise错误处理** (P0) - 影响应用稳定性
3. **链接缓存竞态** (P0) - 影响核心功能
4. **内存泄漏问题** (P1) - 长期运行稳定性
5. **资源管理问题** (P1) - 服务可靠性

## 🛠️ 辅助脚本说明

### backup.sh - 数据备份脚本

**功能：**
- 自动备份配置文件（config.json, .env）
- 备份数据目录（vectors, contexts, cookies）
- 创建带时间戳的备份目录
- 自动清理旧备份（保留最近10个）

**使用：**
```bash

# ========================================
#
# 备份位置: backups/20260205_143022

```

**功能：**
- 从指定备份恢复数据

## ⚠️ 重要注意事项

### 修复前必读

1. **始终先备份**
   ```bash
   ./scripts/backup.sh
   ```

2. **在测试分支工作**
   ```bash
   git checkout -b security-fixes-2026
   ```

3. **一次只修复一个问题**
   - 便于测试
   - 便于回滚
   - 便于代码审查

4. **充分测试后再合并**
   - 运行 `./scripts/test-fixes.sh`
   - 手动测试核心功能
   - 观察应用运行至少2小时

### 修复过程中

1. **保持文档同步**
   - 完成后立即更新 `FIX_PROGRESS.md`
   - 记录遇到的问题和解决方案
   - 更新实际工作量

2. **遵循Git提交规范**
   ```bash
   git commit -m "fix(P0-1): 实现JWT密钥持久化

   - 详细说明修改内容
   - 列出主要变更点

   测试：
   - 测试场景1
   - 测试场景2"
   ```

3. **出现问题立即回滚**
   ```bash
   # 快速回滚到上一个提交
   git reset --hard HEAD~1

   # 或恢复特定文件
   git checkout HEAD -- src/config.js

   # 或从备份恢复
   ./scripts/restore.sh [timestamp]
   ```
