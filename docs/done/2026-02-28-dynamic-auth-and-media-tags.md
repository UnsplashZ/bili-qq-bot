# 2026-02-28 动态认证角标 / 多图标签 / 充电样式优化实施计划

## 1. 背景与目标

本次计划聚焦预览卡片渲染层的四项可见性改造，目标是在不改消息发送链路、不改 API 契约的前提下，完成以下需求：

1. 用户认证标签：仅在`动态卡片`和`用户主页卡片`头像区域增加认证小闪电图标，并兼容头像框。
2. 多图动态标签：在多图动态的图片右下角显示半透明标签，标识`长图`或`动图`。
3. 充电专属标签：移除当前金色浅底文案标签，仅在类型标签后展示一个闪电图标。
4. 充电专属内容文案区：为居中文本增加半透明背景并适度增大字号，提升整体协调性。

## 2. 已确认决策（本轮输入）

1. 充电图标采用`选项A`：跟随类型标签开关；若用户关闭类型标签，则不显示闪电图标。
2. 长图判定阈值：`height / width >= 1.8`。
3. 优先修改范围：先做计划文档，再进入实现。

## 3. 现状链路与问题定位

### 3.1 现状链路

1. 卡片生成入口：`src/services/imageGenerator/generators/previewCard.js`
2. 动态渲染：`src/services/imageGenerator/renderers/dynamic.js`
3. 用户主页渲染：`src/services/imageGenerator/renderers/user.js`
4. 动态媒体渲染：`src/services/imageGenerator/renderers/components/media.js`
5. 统一样式：`src/services/imageGenerator/core/theme.js` + `src/utils/designSystem.js`
6. 上游数据：`src/services/bili_server.py`（动态/视频/用户/专栏）

### 3.2 当前问题

1. 认证信息虽可获取（动态中存在 `module_author.official_verify`），但渲染层未展示认证角标。
2. 动态多图渲染仅传递图片 URL 字符串，丢失宽高和动图标识，无法打`长图/动图`角标。
3. 充电专属标签当前是“金色浅底 + 文案”，视觉权重偏重，与类型标签样式不统一。
4. 充电专属占位内容仅纯文本居中，缺少信息容器感。

## 4. 方案选型

### 4.1 方案 A：保持现状

1. 优点：零风险。
2. 缺点：四项需求均无法满足。

### 4.2 方案 B：仅改样式，不改媒体数据结构

1. 优点：改动较小。
2. 缺点：无法实现多图`长图/动图`标签（缺必要元数据）。

### 4.3 方案 C：渲染层增量改造（推荐）

1. 在不改业务流程的前提下，补齐动态图片元数据透传并增加标签渲染。
2. 认证、充电样式均在渲染层实现，避免触碰消息格式与订阅状态机。
3. 对外行为变化集中在“卡片视觉与信息标识”，范围可控、回滚简单。

结论：采用方案 C。

## 5. 详细改造设计

### 5.1 需求一：认证小闪电（动态卡片 + 用户主页卡片）

#### 5.1.1 数据来源策略

动态卡片：
1. 主来源：`modules.module_author.official_verify.type`
2. 兜底来源：`item.author` 不可靠，不作为主判断
3. 判定规则：`type` 为 `0` 或 `1` 视为已认证，`-1/null` 视为未认证

用户主页卡片：
1. 主来源：`info.dynamic.modules.module_author.official_verify.type`
2. 兜底：若 `dynamic` 缺失则不显示
3. 不依赖 `get_user_info` 顶层 `official/official_verify`（该字段在现有样本中常为空）

#### 5.1.2 渲染策略

1. 在 `avatar-wrapper` 内增加认证角标节点（例如 `<span class="author-verify-badge">⚡</span>` 或等价 SVG）。
2. 角标定位：头像右下区域，绝对定位；层级高于头像与头像框。
3. 与头像框兼容：
   - 角标 `z-index` 高于 `.avatar-frame`
   - 保持 `pointer-events: none`，不影响截图布局
4. 仅在命中认证条件时渲染。

#### 5.1.3 样式策略

1. 提供统一 class（动态/用户主页复用）：
   - 小圆角/圆形徽标
   - 半透明浅底 + 闪电图形
   - 边框与轻微阴影，避免在复杂头像框上丢失可读性
2. 夜间模式沿用现有主题变量，避免硬编码极亮色。

### 5.2 需求二：多图动态 `长图/动图` 右下角标签

#### 5.2.1 数据结构调整

当前：
1. `collectDynamicImages()` 返回 `string[]`（仅 URL）

调整后：
1. 返回 `imageItems[]`，每项至少包含：
   - `url`
   - `width`
   - `height`
   - `liveUrl`（来自 `live_url`）
2. 对 `draw.items` 与 `opus.pics` 统一映射，保证渲染层单一接口。

#### 5.2.2 标签判定规则

每张图独立判定：
1. `动图`优先：
   - `liveUrl` 非空，或
   - `url` 后缀命中 `.gif`（支持 query 参数场景）
2. `长图`其次：
   - `width > 0 && height > 0 && height / width >= 1.8`
3. 其他：不显示角标

冲突策略：
1. 若同时命中动图与长图，显示`动图`（优先级更高）。

#### 5.2.3 展示范围

1. 仅对`多图网格`启用标签（符合需求描述）。
2. 单图场景不强行加角标，避免视觉噪音。
3. 转发原动态中的多图网格沿用同逻辑（保持一致）。

#### 5.2.4 样式策略

1. 每个网格项包裹为容器（支持角标绝对定位）。
2. 标签位于右下角，半透明深底，白字，圆角。
3. 字号与现有 `duration-badge` 协调但更轻量，避免抢主视觉。

### 5.3 需求三：充电专属标签改为“仅闪电图标”

#### 5.3.1 行为规则

1. 保留当前 `detectChargingContent()` 判断逻辑（不改语义）。
2. 类型标签显示时，尾部附加一个`闪电图标`。
3. 类型标签隐藏时（群配置关闭），不显示闪电图标（已确认采用选项A）。

#### 5.3.2 渲染与样式

1. 将 `charging-mark` 从“文本胶囊”改为“纯图标节点”。
2. 移除金色浅底、边框和“充电专属”文案。
3. 闪电图标尺寸、间距与 type badge 字号配平。

### 5.4 需求四：充电专属占位文本视觉优化

#### 5.4.1 渲染结构

1. 保持 `MAJOR_TYPE_BLOCKED` 分支逻辑不变。
2. 在 `charging-blocked-hint` 内增加内容容器（如 `charging-blocked-panel`），承载文本行。

#### 5.4.2 视觉增强

1. 半透明背景（浅色/深色模式分别适配）。
2. 增大字号（相对当前 `font-caption` 略提升）。
3. 增加内边距、圆角、轻微边框与阴影。
4. 多行文本保持居中与行距优化。

## 9. 风险评估与缓解

主要风险：
1. 图片结构改造可能影响现有单图/转发图渲染路径。
2. 认证角标定位在不同头像框下出现偏移。
3. GIF 判定若仅后缀识别，可能有少量非标准 URL 漏判。

缓解措施：
1. 保持函数入参兼容（必要时兼容字符串数组与对象数组双输入）。
2. 角标样式采用保守尺寸与统一锚点，并以多样本截图回归。
3. 动图判定采用双通道：`live_url` + `.gif` 后缀。

## 10. 回滚策略

按功能块独立回滚，避免整包回退：

1. 若多图标签异常：回滚 `dynamic.js + media.js + 对应 CSS`。
2. 若认证角标异常：回滚 `dynamic.js/user.js + 对应 CSS`。
3. 若充电样式不达预期：回滚 `previewCard.js + designSystem.js`。
4. 均为渲染层回滚，不影响订阅状态、消息协议和缓存结构。
