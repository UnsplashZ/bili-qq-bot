# 2026-03-02 二期计划：AI 多模态输入（图片等）支持

## 1. 目标与边界

### 1.1 目标

1. 在模型与接口支持时，将图片等非文本信息传递给 AI。
2. 提供安全降级：不支持或不可达时自动回退为 `[图片]` 文本占位。
3. 保持一期 HTTP-only MCP 成果不被破坏。

### 1.2 非目标

1. 本期不调整 MCP 传输类型策略（沿用一期：仅 `sse/streamable_http`）。
2. 本期不做 UI 大规模改版，仅新增必要配置开关与说明。

## 2. 里程碑

### 里程碑 M1：数据结构升级（兼容旧数据）

完成标准：

1. 上下文消息可同时支持旧版纯文本和新版分段内容结构。
2. 旧历史数据无需迁移即可读取（运行时兼容）。
3. 向量记忆仍按文本策略存储，避免检索链路回归。

### 里程碑 M2：多模态请求构造与降级

完成标准：

1. 当开关开启且模型支持时，AI 请求可携带图片片段。
2. 当模型不支持/图片不可达/超限时，自动降级为文本占位。
3. 错误可观测（日志中可区分“模型不支持”和“图片不可达”）。

### 里程碑 M3：Docker 可用性验证

完成标准：

1. Docker 场景下图片可达路径明确（URL 模式或受限 base64 模式）。
2. 有可执行的尺寸限制与超时策略，避免请求体失控。
3. 回归通过：普通文本对话与 MCP 工具调用不受影响。

## 3. 逐文件改动清单

## 3.1 `src/handlers/messageHandler.js`

改动点：

1. 在接收消息时保留结构化片段（文本、图片）供 AI 使用。
2. 维持当前 `vectorMemory` 的文本写入逻辑（继续去 CQ 后存文本）。
3. 为图片片段提取最小必要字段（可访问 URL 或可控 base64 引用信息）。

风险与备注：

1. 结构化片段只用于 AI 请求构造，不直接改变普通消息处理链路。

## 3.2 `src/services/aiContextService.js`

改动点：

1. 扩展上下文消息模型：兼容 `content: string` 与 `contentParts: []`。
2. 读取时兼容旧数据；写入时支持新结构并保持原子写。
3. 对缓存淘汰与持久化逻辑保持一致，不改 TTL/LRU 策略。

风险与备注：

1. 这是本期最关键兼容点，需严格保证旧文件可无损读取。

## 3.3 `src/handlers/aiHandler.js`

改动点：

1. 新增能力判断：模型是否允许多模态输入（基于配置/白名单）。
2. 构造请求消息时支持 `content` 分段数组（`text` + `image_url`）。
3. 增加统一降级逻辑：
   1. 模型不支持 -> 文本占位。
   2. 图片不可达 -> 文本占位。
   3. 图片超限 -> 文本占位并日志标记。
4. 保持现有工具调用循环与系统提示策略不变。

## 3.4 `src/config.js` 与 `config/.env.example`（或运行时配置）

改动点：

1. 新增多模态相关开关和限制项（默认关闭）：
   1. `aiMultimodalEnabled`（默认 `false`）
   2. `aiMultimodalMaxImages`
   3. `aiMultimodalMaxImageBytes`
   4. `aiMultimodalTransportMode`（`url`/`base64`，默认 `url`）
2. 读配置时提供默认值与合法性校验。

## 3.5 `src/dashboard/routes/api.js` 与 `dashboard/src/pages/Settings.jsx`（可选但建议）

改动点：

1. 后端开放多模态配置字段读写与校验。
2. WebUI 增加最小配置入口（开关 + 限额），并展示“模型需支持视觉输入”提示。

## 3.6 `README.md`

改动点：

1. 增补多模态使用说明（开启条件、模型要求、降级行为）。
2. 增补 Docker 注意事项：
   1. URL 模式下 AI 服务与图片地址的可达关系。
   2. base64 模式下的体积与超时建议。

## 4. 核心设计约束

1. 默认关闭多模态，确保升级后用户体验不变。
2. 任意异常都必须可降级到文本模式，不阻塞主流程。
3. 向量记忆链路保持文本优先，避免检索质量抖动。

## 5. 验证计划

1. 兼容性验证
   1. 旧上下文文件可正常读取并继续对话。
   2. 新旧消息混合上下文可正确构造请求。
2. 功能验证
   1. 开关关闭时：行为与当前一致（`[图片]` 占位）。
   2. 开关开启且模型支持：可读图并给出合理回复。
   3. 开关开启但模型不支持：自动降级为文本占位。
3. 稳定性验证
   1. 图片超限、不可达、超时场景均不致使对话流程中断。
   2. MCP 工具调用能力与一期能力不回退。
4. Docker 验证
   1. 容器网络下 URL 可达或明确不可达时降级生效。

## 6. 回滚方案

1. 关闭 `aiMultimodalEnabled` 开关即可快速回退到纯文本模式。
2. 如需代码回滚，按文件粒度回滚 `messageHandler/aiContextService/aiHandler` 的多模态改造。
3. 保留一期 MCP HTTP-only 改造，不受二期回滚影响。

## 7. DoD

1. 多模态支持在开启时可工作，在异常时可降级。
2. 默认配置下行为与当前版本一致。
3. Docker 场景有明确可达性策略与排障文档。
4. 一期 MCP 调用能力无回归。
