# 预览图氛围色完整预览浮窗计划

## 摘要

- 目标：移除当前容易误导的细长“即时渐变反馈”条，改为“查看预览”按钮 + 完整效果浮窗，让用户看到更接近真实卡片的最终合成观感。
- 范围：仅调整 dashboard 设置页前端交互与本地预览表现，不改后端接口，不改保存协议，不改图片渲染服务端逻辑。

## 关键改动

### 设置页交互

- 在 `GeneralSettingsSection` 中删除当前“即时渐变反馈”细条区域。
- 改为一行操作区：
  - 左侧标题：`预览效果`
  - 辅助文案：`查看固定底板与当前氛围色合成后的卡片观感`
  - 右侧按钮：`查看预览`
- 点击 `查看预览` 打开一个基于现有 `GlassModal` 的预览浮窗。
- 浮窗与颜色选择器互斥：
  - 打开预览浮窗时关闭当前颜色选择器
  - 打开颜色选择器时关闭预览浮窗

### 预览数据流

- 浮窗预览使用“当前编辑态”而不是“最近一次已保存态”。
- 新增一个纯前端的“有效预览颜色”推导逻辑：
  - 对每个字段，若 `gradientInputs[field]` 是合法 `#RRGGBB`，则使用其标准化值
  - 否则回退到 `previewGradientConfig[field]`
- 同一套“有效预览颜色”同时驱动：
  - 预览浮窗
  - 列表中的颜色小色块
- 不改变现有保存逻辑：
  - 仍由 `onSavePreviewGradient` 持久化
  - `GradientColorPickerPopover` 仍保持“点应用颜色才提交到父级状态”的语义

### 预览浮窗内容

- 新增轻量组件：`dashboard/src/pages/settings/components/PreviewGradientModal.jsx`
- 浮窗标题：`预览图效果`
- 说明文案：`这是固定底板与当前氛围色合成后的卡片效果，不等于原始选色本身。`
- 中央展示一张“近似真实卡片”的迷你预览，不调用后端、不生成真实图片：
  - 外层容器直接使用 `buildGradientBackground(color1, color2)`
  - 内层卡片复用 dashboard 的玻璃质感风格
  - 卡片内容使用固定假数据：头像占位、标题、副标题、正文、封面块
- 浮窗底部只保留一个 `关闭` 按钮，不增加保存入口。

### 模块与接口调整

- `previewGradientModel.js`
  - 保留 `buildGradientBackground`
  - 新增一个可复用的纯函数，用于根据 `gradientInputs + previewGradientConfig` 产出“有效预览颜色”
- `GeneralSettingsSection.jsx`
  - 新增浮窗开关状态
  - 将色块、预览按钮、预览浮窗都绑定到“有效预览颜色”
  - 移除旧的细条预览 JSX 和相关文案
- `PreviewGradientModal.jsx`
  - 仅接收 `isOpen`、`onClose`、`color1`、`color2`
- 公共 API / 后端接口 / 配置字段：无变更

## 测试与验收

### 最小验证

- `cd dashboard && npm run build`
- `node test/unit/preview-gradient-theme.test.js`

### 新增测试

- 新增纯逻辑单测，验证“有效预览颜色”推导函数：
  - 合法输入优先使用 `gradientInputs`
  - 非法输入回退 `previewGradientConfig`
  - 输出统一为标准化大写 `#RRGGBB`
- 使用源码字符串断言，验证：
  - `GeneralSettingsSection` 不再包含“即时渐变反馈”旧文案
  - 新增“查看预览”入口
  - 新组件被接入设置页

### 验收场景

- 初始进入页面时，不显示细条预览，只显示“查看预览”按钮。
- 点击“查看预览”后，浮窗打开，能看到完整迷你卡片预览。
- 修改文本输入为合法颜色后，重新打开或保持打开的浮窗都显示新颜色效果。
- 文本输入非法十六进制时，浮窗继续使用最近的已保存配置回退值，不出现异常样式。
- 点击颜色色块打开拾色器，再点“应用颜色”后，浮窗预览与色块同步更新。
- 打开拾色器后再打开预览浮窗，不出现双层弹出叠加。
- 保存、恢复默认氛围色后，浮窗预览与表单状态保持一致。

## 假设与默认决策

- 默认采用现有 `GlassModal`，不做锚点式 popover。
- 默认只做“一张迷你卡片”预览，不做多模板切换，不接真实预览图片。
- 默认不改颜色拾色器的提交模型；拾色器内拖动仍只更新弹层内部草稿，点击“应用颜色”后才进入主表单状态。
- 默认不新增前端测试框架，测试以现有 Node 纯逻辑测试和 dashboard build 验证为主。
