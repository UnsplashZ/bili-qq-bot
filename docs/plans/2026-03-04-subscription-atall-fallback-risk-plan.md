# 订阅推送 `@全体` 自动降级风险清单（2026-03-04）

## 背景

本次改动为订阅/关注同步推送增加了可选 `@全体` 能力，并在 OneBot/NapCat 无权限或额度不足时自动降级为普通消息，避免推送失败。

核心机制：

1. 发送前调用 `get_group_at_all_remain` 探测能力
2. 按群短缓存探测结果（30 秒）
3. 不可用时不拼接 `qq=all`，直接发普通消息

## 可能问题与影响

### 1. 探测与实际发送间的瞬时状态变化

- 现象：探测返回可用，但发送时权限被临时回收或额度耗尽，导致该条消息仍可能失败。
- 影响：极低概率单条消息失败，不会影响后续消息持续降级。
- 现状：已通过“默认可降级 + 下一轮重新探测”降低影响。
- 后续建议：如需更强鲁棒性，可接入 `send_group_msg` 回包兜底重发（去掉 `@all` 后再发送一次）。

### 2. 群规模较大时探测并发带来的额外请求压力

- 现象：大量群同时推送时，会触发较多 `get_group_at_all_remain` 调用。
- 影响：可能增加 WebSocket action 往返量。
- 现状：已做 30 秒缓存，且 action 响应有超时保护。
- 后续建议：必要时可进一步做“单群进行中的探测去重”（同一时刻同群只保留一个探测请求）。

### 3. 不同 OneBot 实现字段差异

- 现象：不同实现可能不返回 `can_at_all`，或仅返回剩余次数字段。
- 影响：误判风险（通常偏保守，宁可不 `@all`）。
- 现状：已兼容 `can_at_all` 与 `remain_at_all_count_for_uin/group` 两套字段，异常时直接降级。
- 后续建议：线上采样日志确认各环境实际返回结构，再按真实字段收敛逻辑。

### 4. 日志噪声增加

- 现象：无权限群在每次缓存过期后都会记录一次降级日志。
- 影响：日志量增加，可能掩盖其他告警。
- 现状：当前日志级别为 `info`，便于早期观察。
- 后续建议：稳定后可改为采样记录，或在同群连续相同原因时降噪。

## 回归关注点

1. 文本推送路径与图文推送路径都必须复用同一降级逻辑
2. 订阅去重缓存逻辑（`notificationHistory`）不能被破坏
3. WebSocket 重连后缓存应清空，避免使用旧连接状态
4. 失败降级不能影响主流程定时任务执行

## 结论

当前方案以“保守降级优先”为原则，目标是避免因 `qq=all` 权限不足导致整条订阅消息失败。已知风险主要是极端时序下的单条失败与日志噪声，整体风险可控。
