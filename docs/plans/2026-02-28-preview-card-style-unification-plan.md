# 2026-02-28 预览卡片风格统一修复方案（低风险分阶段）

## 1. 背景与目标

当前预览卡片（`src/services/imageGenerator`）整体可用，但存在 6 类风格不统一点。用户反馈中明确指出：

1. 专栏卡片正文与底部数据栏之间缺少分割线（动态卡片正常）。
2. 除专栏外，其他卡片当前排版“基本没太大问题”。

因此本方案目标是：

1. 修复已确认的不统一点，优先解决专栏视觉分区问题。
2. 不影响当前功能正确执行（数据流、渲染流程、输出契约保持不变）。
3. 不对当前视觉效果产生明显负面影响（除专栏增强外，其他卡片保持原有观感基线）。
4. 修复过程中不引入无关变量（不新增配置项、不改 API、不引入额外依赖、不做无关重构）。

## 2. 约束与非目标

### 2.1 硬性约束

1. 不改动业务语义：仅改样式组织与等价视觉呈现，不改卡片文案、数据来源、消息流程。
2. 不改动输出链路：`generatePreviewCard -> renderer -> screenshot` 主路径保持一致。
3. 不新增运行时开关：不增加 feature flag、环境变量、群配置项。
4. 不做无关“顺手优化”：只触达本方案列出的文件和样式点。

### 2.2 非目标

1. 不重做整套设计语言。
2. 不调整现有信息密度（除专栏分区线外不主动放大版式变化）。
3. 不改动订阅检测、链接解析、发送逻辑等后端行为。

## 3. 方案选型

### 3.1 方案 A：保持现状

1. 优点：零风险。
2. 缺点：已知不一致持续存在，专栏问题不解决。

### 3.2 方案 B：一次性全面重构样式系统

1. 优点：理论上一致性最高。
2. 缺点：改动面大、回归风险高，与“其他卡片基本可用”的现实约束冲突。

### 3.3 方案 C：分阶段最小改动统一（推荐）

1. 第一阶段只做“高收益、低风险”修复，优先解决专栏和主题一致性问题。
2. 第二阶段做“等价重构”统一（主要是内联样式落地为 class），不改变数值和版式结构。
3. 每个点独立可回滚，避免一次性放大风险。

结论：采用方案 C。

## 4. 六个问题的详细修复设计

### 4.1 专栏正文与数据栏缺分割线

**现状**

1. `article` 渲染里底部统计栏仅有 `margin-top`，无分隔结构。
2. 动态卡片有 `action-bar` 的上边框与内边距，层次更清晰。

**调整方案**

1. 在专栏统计栏引入专用 class（例如 `article-stats`），由 CSS 统一控制：
   - `border-top: 1px solid var(--color-border)`
   - `padding-top: 20px`
   - 保留原有间距基线（`margin-top` 不做激进改动）。
2. 专栏统计栏结构不变，仅替换内联样式到 class。

**预期效果**

1. 正文区与数据区边界清晰，阅读连续性更好。
2. 与动态卡片的数据区呈现风格统一。

**风险与回滚**

1. 风险：分割线过重导致视觉压迫。
2. 缓解：使用现有变量 `var(--color-border)`，不引入更高对比色。
3. 回滚：仅回退 `article-stats` class 接入与对应 CSS。

---

### 4.2 动态内直播推荐子卡片硬编码浅色值

**现状**

1. `renderMediaHtml` 的 `isLiveRcmd` 分支存在 `#eee/#f9f9f9/#666` 硬编码。
2. 夜间模式下会出现与整体主题不一致的亮色块。

**调整方案**

1. 新增语义 class（如 `live-rcmd-card/live-rcmd-content/live-rcmd-meta`）。
2. 颜色替换为现有主题变量：
   - 边框：`var(--color-border)`
   - 背景：`var(--color-soft-bg)`
   - 文本：`var(--color-subtext)`
3. 几何参数保持不变（圆角、内边距、字号、布局结构不变）。

**预期效果**

1. 浅色模式视觉基本等价。
2. 深色模式消除突兀亮块，与全卡片主题一致。

**风险与回滚**

1. 风险：变量替换后浅色模式层次略有变化。
2. 缓解：仅替换颜色，不改 spacing 和字体。
3. 回滚：恢复 `isLiveRcmd` 分支的 class 映射即可。

---

### 4.3 专栏样式入口不一致（`.article-body` 未实用）

**现状**

1. 主题中已定义 `.article-body` 的专栏排版规则（标题、引用、代码块等）。
2. 实际渲染使用 `.text-content`，导致专栏样式能力未生效。

**调整方案**

1. 仅对 `html_content` 路径启用 `.article-body`。
2. `summary` 文本回退路径保持 `.text-content`（避免非 HTML 内容视觉突变）。
3. 不改正文内容来源与清洗逻辑，只改 class 绑定策略。

**预期效果**

1. 专栏 HTML 正文获得预期排版层次。
2. 普通摘要路径保持当前视觉风格，避免大面积变化。

**风险与回滚**

1. 风险：某些历史 HTML 内容样式差异扩大。
2. 缓解：先覆盖常见样本（含标题/引用/图片/代码块）做截图对比。
3. 回滚：恢复到 `.text-content` 单路径。

---

### 4.4 内联样式过多，难以统一维护

**现状**

1. `user/live/dynamic` 存在大量 `style=""`，导致样式入口分散。
2. 同类元素（徽标、头像区域、统计块）难以全局一致调整。

**调整方案**

1. 采取“等价迁移”策略：
   - 将静态内联样式迁移为 class。
   - 动态依赖数据的样式（如粉丝牌颜色）保留最小内联。
2. 迁移时不改任何数值（字号/间距/圆角/宽高完全保持）。
3. 按模块分批：先 `live` 和 `media`，后 `user` 与 `dynamic`。

**预期效果**

1. 输出视觉近似不变。
2. 后续统一改样式时可集中在 `theme.js`，减少分叉。

**风险与回滚**

1. 风险：class 迁移时遗漏属性导致细节偏移。
2. 缓解：每次迁移单文件、单点提交，逐卡片对比。
3. 回滚：按提交粒度回退，不影响其他点。

---

### 4.5 媒体块间距规则冲突（class 与内联重复）

**现状**

1. 图片网格与单图块既有 class 间距，又叠加内联 `margin-top`。
2. 在“原动态/普通动态/多图”场景中出现 10/20/24px 混用。

**调整方案**

1. 统一由 class 管理顶部间距，移除重复内联间距。
2. 保留原动态与普通动态的差异，但改为语义 class（如 `is-orig` 变体类），避免硬编码分散。
3. 不改网格列数逻辑和媒体尺寸逻辑。

**预期效果**

1. 不同媒体场景间的垂直节奏更稳定。
2. 布局结构不变，用户感知变化应接近“更整齐”而非“样式大改”。

**风险与回滚**

1. 风险：部分场景间距略变导致卡片长度变化。
2. 缓解：保持原有数值集合，只统一入口，不重设计数值。
3. 回滚：恢复内联 `margin-top` 即可。

---

### 4.6 样式入口分叉（Badge/富文本局部内联）

**现状**

1. Type Badge 有设计系统统一函数，但预览卡片使用独立实现。
2. 富文本 URL/BV 节点仍使用内联着色样式。

**调整方案**

1. 第一阶段不强制切换到新渲染函数，避免入口替换带来结构回归。
2. 先做“视觉统一最小步”：
   - URL/BV 改为 class（如 `.rich-link`）。
   - Badge 保持现有 HTML 结构，只统一样式来源。
3. 第二阶段再评估是否合并渲染入口（前提：截图差异可控）。

**预期效果**

1. 视觉统一增强且风险可控。
2. 不因大规模入口重构影响当前稳定输出。

**风险与回滚**

1. 风险：入口合并时可能影响 badge 文案可见性。
2. 缓解：本期先不改入口，只做样式层合并。
3. 回滚：恢复对应 class 绑定即可。

## 5. 实施顺序（防回归）

### 阶段 0：基线固化（不改代码行为）

1. 采样卡片：视频、番剧、直播、动态（含转发/投票/图文）、用户、专栏，覆盖浅色/深色。
2. 生成并保存“改前基线图”用于肉眼对比。
3. 记录每类卡片关键检查点（标题换行、头像框、统计栏、媒体块间距）。

### 阶段 1：高收益低风险修复（推荐先落地）

1. 4.1 专栏分割线。
2. 4.2 直播推荐子卡片变量化。
3. 4.3 专栏 `article-body` 接入（仅 HTML 路径）。

### 阶段 2：等价统一（保持视觉基线）

1. 4.4 内联样式 class 化（静态样式）。
2. 4.5 媒体间距入口统一。
3. 4.6 富文本与 badge 样式入口收敛（先样式后函数入口）。

## 7. 验证计划（功能与视觉）

### 7.1 功能正确性验证

1. 预览生成主链路可用：各类型卡片能正常生成图片，无崩溃。
2. 特殊场景可用：动态转发、投票、直播推荐、专栏 HTML 内容。
3. 不应出现字段读取异常或空对象访问异常。

### 7.2 视觉回归验证

1. 除专栏外，其他卡片不应出现明显负面变化：
   - 不错位
   - 不重叠
   - 不截断异常
   - 不出现突兀亮色块
2. 专栏应出现明确分区改善：
   - 正文与底部数据区边界更清晰
   - HTML 正文层次增强
3. 浅色/深色均需对比。

### 7.3 静态检查建议

1. 检查目标目录中的硬编码颜色是否减少（尤其 `#eee/#f9f9f9/#666`）。
2. 检查新增 class 是否集中在 `theme.js` 管理。
3. 检查是否误引入无关变量或新配置项。

## 8. 风险与回滚策略

### 8.1 风险

1. class 迁移导致局部样式遗漏。
2. 专栏 HTML 样式增强带来个别内容高度变化。
3. 批量修改时引入无关调整。

### 8.2 控制策略

1. 单点改动、分点提交、逐点验收。
2. 严格按“仅样式入口统一，不变更布局数值”为原则。
3. 每个点均可独立回滚，不绑死在一个大补丁中。

### 8.3 回滚方案

1. 任一修复点出现负面影响，回滚该点对应提交。
2. 若阶段 2 出现回归，可保留阶段 1 成果，暂停等价统一项。

## 9. 验收标准（DoD）

1. 六个问题都有明确处理路径并完成对应验证。
2. 功能正确性无回归（预览生成链路稳定）。
3. 专栏卡片分区问题修复完成，视觉层次提升。
4. 除专栏增强外，其他卡片观感保持稳定，无明显负面变化。
5. 未引入无关变量、无无关重构、无接口/配置语义变化。
